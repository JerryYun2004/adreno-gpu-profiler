# Daily Technical Report — Enabling KGSL Adreno Performance Counter Reads Without Kernel Reflash

## Date

2026-06-08

## Project Context

This work is part of the mobile GPU profiling project targeting a rooted OnePlus phone with Qualcomm Adreno 830 GPU exposed through KGSL at:

```text
/dev/kgsl-3d0
/sys/class/kgsl/kgsl-3d0
```

The goal for today was to investigate why direct KGSL performance-counter reads failed with `EPERM`, determine whether reflashing or modifying the Linux kernel was required, and attempt to enable raw hardware-counter reads from rooted userspace.

---

## 1. Initial Problem

Previous KGSL performance-counter ioctl experiments showed the following pattern:

```text
PERFCOUNTER_QUERY: succeeds
PERFCOUNTER_GET: succeeds
PERFCOUNTER_READ: fails with errno=1 EPERM
PERFCOUNTER_PUT: succeeds
```

This suggested that the KGSL driver allowed userspace to query and reserve counters, but blocked actual counter reads.

The main research question was:

```text
Do we need to modify and reflash the OnePlus kernel to enable Adreno hardware counter reads,
or is there a runtime permission/configuration switch?
```

## 4. Source-Level Finding: Why `PERFCOUNTER_READ` Returned `EPERM`

The key file was:

```text
vendor/qcom/opensource/graphics-kernel/adreno_ioctl.c
```

The relevant function was:

```c
static long adreno_ioctl_perfcounter_read(struct kgsl_device_private *dev_priv,
		unsigned int cmd, void *data)
{
	struct adreno_device *adreno_dev = ADRENO_DEVICE(dev_priv->device);
	struct kgsl_perfcounter_read *read = data;

	/*
	 * When performance counter zapping is enabled, the counters are cleared
	 * across context switches. Reading the counters when they are zapped is
	 * not permitted.
	 */
	if (!adreno_dev->perfcounter)
		return -EPERM;

	return (long) adreno_perfcounter_read_group(adreno_dev, read->reads,
		read->count);
}
```

This showed that `EPERM` was not caused by a generic Linux capability check such as:

```text
CAP_SYS_ADMIN
CAP_PERFMON
SELinux denial
device node permission
```

Instead, the read path was blocked by a driver-internal runtime flag:

```c
adreno_dev->perfcounter
```

If this flag was false, the driver intentionally returned:

```c
-EPERM
```

This exactly matched the previous ioctl behaviour.

## 5. Source-Level Finding: Where the Flag Is Controlled

We then searched for assignments and sysfs handling of `adreno_dev->perfcounter`:

```sh
grep -RIn "adreno_dev->perfcounter\|\.perfcounter\|perfcounter =" \
  vendor/qcom/opensource/graphics-kernel \
  2>/dev/null | tee ~/github/adreno_dev_perfcounter_assignments.txt
```

Important results included:

```text
vendor/qcom/opensource/graphics-kernel/adreno.c:1470:
    adreno_dev->perfcounter = false;

vendor/qcom/opensource/graphics-kernel/adreno_sysfs.c:408:
    return adreno_dev->perfcounter;

vendor/qcom/opensource/graphics-kernel/adreno_sysfs.c:413:
    if (adreno_dev->perfcounter == val)

vendor/qcom/opensource/graphics-kernel/adreno_sysfs.c:416:
    return adreno_power_cycle_bool(adreno_dev, &adreno_dev->perfcounter, val);
```

This showed that:

1. The driver initializes `adreno_dev->perfcounter` to `false`.
2. The flag is exposed through a sysfs interface.
3. The sysfs store path can update the flag and power-cycle the GPU as needed.

This suggested that kernel reflashing might not be necessary if the sysfs node was exposed and writable on the phone.

## 7. Exact Action That Enabled KGSL Perfcounter Reads

The permission was enabled by writing `1` to the sysfs node as root:

```sh
adb shell 'su -c "echo 1 > /sys/class/kgsl/kgsl-3d0/perfcounter"'
```

Then verify:

```sh
adb shell 'su -c "cat /sys/class/kgsl/kgsl-3d0/perfcounter"'
```

Expected output:

```text
1
```

This directly toggled the driver’s `adreno_dev->perfcounter` flag.

This was the key step that avoided kernel reflashing.

## 17. Final Conclusion

We do not need to reflash the Linux kernel for the current KGSL perfcounter read-permission issue.

The original `EPERM` was caused by this driver-level condition:

```c
if (!adreno_dev->perfcounter)
    return -EPERM;
```

The relevant runtime flag is exposed through sysfs:

```text
/sys/class/kgsl/kgsl-3d0/perfcounter
```

Root can enable it directly:

```sh
adb shell 'su -c "echo 1 > /sys/class/kgsl/kgsl-3d0/perfcounter"'
```

After enabling this node, KGSL performance-counter reads succeed through ioctl:

```text
PERFCOUNTER_QUERY: OK
PERFCOUNTER_GET: OK
PERFCOUNTER_READ: OK
PERFCOUNTER_PUT: OK
```

This means the project can proceed using rooted userspace + KGSL ioctls without kernel reflashing for basic direct hardware-counter access.

1. Repeat candidate counter sweeps across multiple runs to compute mean and standard deviation.
2. Keep a small candidate set:

   ```text
   SP 2   — ALU-sensitive candidate
   SP 11  — possible work-item/invocation normalization counter
   SP 1   — memory-sensitive candidate
   SP 8   — strong memory-sensitive candidate
   SP 10  — similar to SP 8
   SP 14  — memory-sensitive candidate
   SP 4   — highly memory-selective candidate
   SP 7   — memory-selective candidate
   ```

3. Build a real-time sampler that:

   * enables `/sys/class/kgsl/kgsl-3d0/perfcounter`;
   * reserves selected counters with `PERFCOUNTER_GET`;
   * reads them repeatedly with `PERFCOUNTER_READ`;
   * releases them with `PERFCOUNTER_PUT`;
   * logs counter deltas with timestamps;
   * correlates results with KGSL sysfs busy, pwrstats, ram-wait, and tracepoints.
4. Record this finding as a major project milestone:

   ```text
   Direct KGSL hardware-counter reads are possible from rooted userspace on the target OnePlus/Adreno 830 device without reflashing the kernel, provided that the KGSL sysfs perfcounter flag is enabled.
   ```
